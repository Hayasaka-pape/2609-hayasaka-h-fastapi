# API 自動テスト

`fastapi_app` ディレクトリで仮想環境を有効にし、依存をインストールして実行します。

```bash
python -m pip install -r requirements.txt
python -m pytest -q
```

## 対象と接続先

FastAPI の `TestClient` から実ルーターを呼び、Pydantic の入力検証、HTTP 応答、SQLAlchemy のモデルとデータアクセス層をまとめて検証します。テストごとに pytest の一時ディレクトリに SQLite DB を作成し、アプリ起動時のエンジンと DB セッションの依存関係をその DB に置き換えます。SQLite の外部キー制約も有効にしています。

MySQL-Sample や `.env` はこの自動テストの実行に不要です。利用者の `test_db` に接続せず、既存データを変更・削除しません。

## 確認する受け入れ条件

- カテゴリ・担当者付きの日本語タスクを作成 → 一覧・1件取得 → 完了切替 → 編集 → 削除する。
- 作成時は未完了、日時があり、レスポンスにカテゴリ・担当者が入れ子で含まれる。
- POST は 201、DELETE は 204 かつ本文が空で、タスク削除後も参照先は残る。
- カテゴリと担当者を別の値に変更し、`null` で関連・説明を解除できる。
- `is_done=false`、`is_done=true`、カテゴリ単独と AND 条件で絞り込める。
- カテゴリ・担当者の一覧に 100 件を超えて登録した項目も含まれる。
- 空白だけの名前やタイトル、上限超過、不正な型・ID が 422 になる。
- PUT の全 5 項目が必須で、検証失敗時に元のタスクが変わらない。
- 不明なタスクや参照 ID は 404、名前の重複は 409 になり、その後の登録が成功する。
- フロントエンドの両オリジンで JSON 更新の CORS プリフライトと応答が許可される。
- DB の INSERT 後に commit が失敗すると一般的な 500 を返し、内部情報を返さず、未確定の行が残らない。その後の保存も成功する。

## 実環境の確認との違い

このテストは MySQL の照合順序や Docker のデータボリューム、ブラウザでの画面操作を検証しません。実際の MySQL-Sample への保存、FastAPI 再起動および MySQL コンテナ再作成後の永続化、画面操作の記録は [../../screenshots/README.md](../../screenshots/README.md) を参照してください。
